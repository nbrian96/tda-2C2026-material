Fórmulas y Recetas Rápidas de Parcial

1. Algoritmos de Aproximación

$$\max\left(\frac{\text{Aprox}}{\text{OPT}}, \; \frac{\text{OPT}}{\text{Aprox}}\right) \le \alpha$$
  • Minimización: Cota inferior $L \le \text{OPT}$. Si $\text{Aprox} \le \alpha L \implies \text{Aprox} \le \alpha \text{OPT}$.
  • Maximización: Cota superior $U \ge \text{OPT}$. Si $\text{Aprox} \ge \alpha U \implies \text{Aprox} \ge \alpha \text{OPT}$.
  • Set Cover Voraz: Factor $H(d^*) = \sum_{i=1}^{d^*} 1/i \le \ln(d^*) + 1$.
  • Vertex Cover LP: Relajación $x_v \in [0, 1]$, redondear $x_v \ge 0.5 \implies$ Factor $2$.
  • Christofides TSP: $MST + \text{Matching Impar} \le 1 + 0.5 = 1.5 \implies$ Factor $3/2$.

2. Algoritmos Randomizados

  • Monte Carlo: Tiempo determinístico polinomial, respuesta correcta con probabilidad $1 - \delta$.
  • Las Vegas: Respuesta siempre correcta, tiempo es variable aleatoria con $E[T] = O(n^k)$.
  • Karger Min-Cut: $P(\text{éxito en 1 paso}) \ge \frac{2}{n(n-1)}$. En $\binom{n}{2} \ln n$ corridas: $P(\text{falla}) \le 1/n$.
  • MAX 3-SAT: $E[\text{cláusulas sat}] = \frac{7}{8} m = 0.875 m$.
  • Desigualdad de Markov: $P(X \ge a) \le \frac{E[X]}{a}$ para $X \ge 0, a > 0$.

3. Teorema Maestro (División y Conquista)

$$T(n) = a \cdot T(n/b) + \Theta(n^c) \quad (a \ge 1, \; b > 1, \; c \ge 0)$$
  • Caso 1 (Hojas dominan): Si $\log_b a > c \implies T(n) = \Theta(n^{\log_b a})$
  • Caso 2 (Balance): Si $\log_b a = c \implies T(n) = \Theta(n^c \log n)$
  • Caso 3 (Raíz domina): Si $\log_b a < c \implies T(n) = \Theta(n^c)$

4. Esquema de 4 Pasos Obligatorios para NP-C

  1. Certificado y Verificador en NP: Definir certificado polinomial $C$ y verificador en $O(n^k)$.
  2. Problema conocido en NPC: Seleccionar problema base $A \in \text{NPC}$ y reducir $A \le_P B$.
  3. Transformación polinomial: Definir $f(I_A) \to I_B$ computable en tiempo polinomial.
  4. Demostración Bidireccional: Ida y Vuelta.

Visión Panorámica

0. El Dilema de la Complejidad: ¿Qué hacer ante un Problema NP-Hard?

Hasta ahora vimos que ante problemas de optimización tratamos de hallar la solución óptima exacta mediante Greedy (cuando se cumple subestructura óptima y elección voraz), Programación Dinámica (subproblemas superpuestos), Redes de Flujo (algoritmos polinomiales exactos), o Backtracking / Branch & Bound / Programación Lineal Entera (PLE) (que garantizan el óptimo pero con costo temporal exponencial en el peor caso).

"En ocasiones, es preferible una buena solución rápida, que una solución óptima demasiado tarde." (Clase oficial TDA). Cuando el tamaño de entrada $N$ crece a miles o millones, un algoritmo de $O(2^N)$ o $O(N!)$ tardaría más que la edad del universo.

📏 Algoritmos de Aproximación

Garantía matemática determinista de calidad

  • Corren en tiempo polinomial $O(n^k)$.
  • Devuelven una solución factible cuya distancia al óptimo desconocido está acotada por un factor $\alpha$.
  • Minimización: $\text{Costo}(S) \le \alpha \cdot \text{OPT}$ con $\alpha \ge 1$ (ej: 2-aproximación).
  • Maximización: $\text{Beneficio}(S) \ge \alpha \cdot \text{OPT}$ con $\alpha \le 1$ (ej: 0.5 o $7/8$).
🎲 Algoritmos Randomizados

El azar como recurso algorítmico deliberado

  • El algoritmo toma decisiones basadas en generación de aleatoriedad.
  • Monte Carlo: Tiempo de ejecución acotado/polinomial garantizado; respuesta correcta con alta probabilidad (error acotado $\le 1/n$).
  • Las Vegas: Respuesta siempre correcta garantizada; tiempo de ejecución es una variable aleatoria con esperanza polinomial $E[T] = O(n)$.
  • Destruyen configuraciones adversarias (evitan el peor caso de algoritmos determinísticos).
Teoría Fundamental

1. Fundamentos de Aproximación y el Problema de las Cotas

Para demostrar que un algoritmo entrega una $\alpha$-aproximación, debemos probar que para toda entrada factible:

🎯 Razón de Aproximación (Approximation Ratio)
$$\max\left( \frac{\text{Aprox}}{\text{OPT}}, \; \frac{\text{OPT}}{\text{Aprox}} \right) \le \alpha$$

Un algoritmo es una 2-aproximación para minimización si nunca gasta más del doble del óptimo.

⚠️ El gran obstáculo pedagógico: No conocemos la solución óptima $\text{OPT}$ (calcularla requeriría resolver el problema NP-Hard en tiempo exponencial). Por lo tanto, es obligatorio encontrar una cota o límite estructural o matemático:
  • En problemas de Minimización: Se busca una cota inferior $L \le \text{OPT}$. Si demostramos que $\text{Aprox} \le \alpha \cdot L$, como $L \le \text{OPT}$, automáticamente $\text{Aprox} \le \alpha \cdot \text{OPT}$.
  • En problemas de Maximización: Se busca una cota superior $U \ge \text{OPT}$. Si probamos que $\text{Aprox} \ge \alpha \cdot U$, entonces $\text{Aprox} \ge \alpha \cdot \text{OPT}$.
Esquemas de Aproximación (PTAS y FPTAS)

Para ciertos problemas, podemos fijar un margen de error $\epsilon > 0$ deseado (por ejemplo, estar a menos del $1\%$ del óptimo):

  • PTAS (Polynomial-Time Approximation Scheme): Para cualquier $\epsilon > 0$ fijo, corre en tiempo polinomial en $n$, pero la constante depende de $\epsilon$, por ejemplo $O(n^{1/\epsilon})$ o $O(n^{k+1})$. Si $\epsilon \to 0$, el exponente puede explotar.
  • FPTAS (Fully Polynomial-Time Approximation Scheme): El tiempo es polinomial tanto en el tamaño de entrada $n$ como en $1/\epsilon$, por ejemplo $O(n^3 \cdot \epsilon^{-1})$. ¡Es el estándar dorado de la aproximación!
Caso de Estudio 1

2. Set Cover Aproximado (Voraz con Cota Armónica)

Definición del Problema: Dado un universo $U$ de elementos y una colección de subconjuntos $S = \{S_1, S_2, \dots, S_m\}$ donde cada $S_i \subseteq U$ tiene un costo asociado $w_i \ge 0$, se busca encontrar una subcolección $C \subseteq S$ tal que $\bigcup_{S_i \in C} S_i = U$ minimizando el costo total $\sum_{S_i \in C} w_i$.

Regla Voraz de Selección: En cada iteración, no elegimos simplemente el de menor peso ni el de más elementos. Elegimos el subconjunto $S_i$ que tenga el menor costo por elemento nuevo cubierto:

$$\text{Elegir } S_i \text{ que minimice } \frac{w_i}{|S_i \cap R|}$$

Donde $R \subseteq U$ es el conjunto de elementos que aún permanecen sin cubrir.

Caso de Estudio 2

3. Vertex Cover: Aproximación por Relajación Lineal (Rounding)

En Vertex Cover Ponderado, tenemos un grafo $G=(V, E)$ y cada vértice $v_i$ tiene peso $w_i \ge 0$. Buscamos $S \subseteq V$ de costo mínimo tal que toda arista $(i, j) \in E$ tenga al menos un extremo en $S$.

1. Modelo Entero (PLE) — NP-Hard
$$\min \sum_{i \in V} w_i X_i$$ $$\text{s.a.} \quad X_i + X_j \ge 1 \quad \forall (i, j) \in E$$ $$X_i \in \{0, 1\}$$

Resolverlo exactamente es NP-Hard (en la lista de los 21 problemas de Karp).

2. Relajación Lineal (RL) — Polinomial
$$\min \sum_{i \in V} w_i X_i$$ $$\text{s.a.} \quad X_i + X_j \ge 1 \quad \forall (i, j) \in E$$ $$\mathbf{0 \le X_i \le 1}$$

Se eliminó la restricción de integralidad. Es resoluble en tiempo polinomial (ej. Simplex / Puntos Interiores).

La Técnica de Redondeo (Rounding) y Demostración de la 2-Aproximación
  1. Cota de Relajación: Como la región factible continua contiene a todos los puntos enteros $\{0, 1\}$, el mínimo continuo es igual o mejor que el entero: $$w(S_{RL}) \le w(S^*) \quad (\text{Cota Inferior})$$
  2. Regla de Redondeo: Sea $\{X_i^*\}$ la solución fraccionaria de la RL. Definimos el conjunto aproximado: $$S = \{i \in V : X_i^* \ge 0.5\}$$
  3. Factibilidad garantizada: Para cualquier arista $(i, j) \in E$, la restricción exige $X_i^* + X_j^* \ge 1$. Por el principio del palomar, es matemáticamente imposible que ambos sean menores a $0.5$. Al menos uno debe tener $X^* \ge 0.5$, por lo que al menos un extremo entra a $S$. ¡$S$ siempre es un Vertex Cover válido!
  4. Acotación del costo: $$\sum_{i \in S} w_i \le \sum_{i \in S} 2 w_i X_i^* \le 2 \sum_{i \in V} w_i X_i^* = 2 w(S_{RL}) \le 2 w(S^*)$$ Conclusión: El costo es a lo sumo el doble del óptimo. ¡Es una 2-aproximación!
⚠️ ¡Peligro de Parcial!: Reducciones de Decisión vs Reducciones en Aproximación
Sabemos que $IndependentSet \le_P VertexCover$ (un conjunto $I$ es independiente sii su complemento $V \setminus I$ es Vertex Cover). Sin embargo, no se puede usar un algoritmo de aproximación de Vertex Cover para resolver Independent Set. Si un grafo tiene 1000 nodos, $VC^* = 10$ e $IS^* = 990$, una 2-aproximación de VC puede costar 20 nodos. Su complemento tendrá $1000 - 20 = 980$ nodos (apenas un error despreciable). Pero si $VC^* = 990$ e $IS^* = 10$, una 2-aproximación de VC podría devolver un cover de tamaño 995, dejando un conjunto independiente de solo 5 nodos (¡la mitad del óptimo!), perdiendo por completo la razón de aproximación.
Caso de Estudio 3

4. Vertex Cover por Pricing Method (Método Primal-Dual)

Introducido por Dantzig, Ford y Fulkerson (1956). Plantea una metáfora económica: Las aristas son "clientes" que pagan un precio $p_e \ge 0$ para ser cubiertas por alguno de los vértices que las tocan.

  • Precio Acorde (Fair): Sería abusivo cobrarle a las aristas más de lo que cuesta el vértice que las cubre. Por lo tanto, para cada vértice $v_i$: $$\sum_{e \text{ incidente a } v_i} p_e \le w_i$$
  • Definición: Un vértice está completamente pago sii $\sum_{e \text{ inc } v_i} p_e = w_i$.
  • Cota Inferior: Para cualquier solución óptima $S^*$, como cubre todas las aristas y cada vértice cobra a lo sumo su peso: $$\sum_{e \in E} p_e \le \sum_{i \in S^*} \sum_{e=(i, j)} p_e \le \sum_{i \in S^*} w_i = w(S^*)$$
  • Factor 2 de Aproximación: Como una arista $e=(u,v)$ tiene 2 extremos, a lo sumo aporta su precio $p_e$ dos veces si ambos extremos terminan en la solución $S$: $$w(S) = \sum_{i \in S} w_i = \sum_{i \in S} \sum_{e \text{ inc } i} p_e \le 2 \sum_{e \in E} p_e \le 2 w(S^*)$$

Caso de Estudio 4

5. El Problema de la Mochila: Heurísticas, Cotas y FPTAS

En la Mochila 0-1 estándar tenemos capacidad $W$ y $n$ elementos con peso $w_i$ y beneficio $v_i$. Buscamos maximizar el valor sin superar la capacidad.

Greedy 1.0 vs Greedy 2.0

Ordenar por densidad $v_i / w_i$ y tomar en orden voraz puede ser arbitrariamente malo (ej. ítem 1 de peso 1 beneficio 2, ítem 2 de peso $W$ beneficio $W$).

Greedy 2.0 (Garantía 0.5): Sea $Z'$ el valor obtenido por la heurística voraz, y $P_c$ el beneficio del elemento crítico (el primer elemento que no entró). Definimos: $$Z'' = \max(Z', \; P_c)$$ Como $Z_{\text{opt}} < Z' + P_c$, ¡uno de los dos debe ser al menos $\frac{1}{2} Z_{\text{opt}}$!
Cotas Superiores: Relajación y Martello-Toth
  • Cota 1 (Relajación Lineal Continua): Se permite fraccionar el elemento crítico $c$: $$U_1 = Z' + \bar{c} \cdot \frac{P_c}{W_c}$$
  • Cota 2 (Martello y Toth 1990): En vez de fraccionar el elemento crítico, se consideran 2 ramas enteras: incluirlo obligatoriamente o excluirlo, tomando $U_2 = \max(W_1, W_2)$. Cota mucho más ajustada.
  • PTAS de Sahni (1975): Probar por fuerza bruta todos los subconjuntos de hasta $k$ elementos fijos y completar con greedy. Complejidad $O(n^{k+1})$, factor $k/(k+1)$.
FPTAS para Mochila mediante Escalado de Beneficios

El algoritmo clásico de Programación Dinámica corre en $O(n W)$ (pseudopolinomial). Si $W$ es gigante, no sirve. Sin embargo, existe una formulación dual de Programación Dinámica basada en el beneficio: $OPT(i, V)$ = mínima capacidad requerida para alcanzar exactamente el beneficio $V$ con los primeros $i$ elementos. Corre en $O(n^2 \cdot v^*)$ donde $v^* = \max v_i$.

🎯 Algoritmo FPTAS de Escalado (Rounding and Scaling)
  1. Fijamos el parámetro de precisión deseado $\epsilon > 0$.
  2. Definimos el factor de escala: $$b = \frac{\epsilon}{2n} \cdot \max_{i} (v_i)$$
  3. Redondeamos el beneficio de cada ítem a múltiplos de $b$: $$\tilde{v}_i = \left\lceil \frac{v_i}{b} \right\rceil \cdot b$$
  4. Resolvemos la nueva instancia reescalada usando la Programación Dinámica dual en $O(n^2 \tilde{v}^*)$.
$$\text{Complejidad Final} = O\left(n^3 \cdot \frac{1}{\epsilon}\right) \quad \text{con garantía} \quad \sum_{i \in S} v_i \ge (1 - \epsilon) \cdot \text{OPT}$$

Es totalmente polinomial en $n$ y en $1/\epsilon$.

Caso de Estudio 5

6. Balanceo de Carga (Load Balancing / Makespan)

Disponemos de $m$ máquinas idénticas y $n$ tareas con duraciones $t_1, t_2, \dots, t_n$. Buscamos asignar cada tarea a una máquina de modo de minimizar la carga máxima o makespan $T = \max_{i} T_i$.

1. Algoritmo Greedy de Graham (List Scheduling)

Regla Voraz: Procesar las tareas en el orden en que llegan y asignar la tarea $j$ a la máquina que tenga menor carga actual.

Demostración de la 2-Aproximación:
Cota A: $T^* \ge \frac{1}{m} \sum t_j$ (promedio ideal).
Cota B: $T^* \ge \max_j t_j$ (la tarea más larga).
Sea $M_i$ la máquina que terminó con la carga máxima $T$, y sea $t_j$ su última tarea asignada. Antes de recibir $t_j$, su carga era $T_i - t_j$. Como era la de menor carga: $$T_i - t_j \le \frac{1}{m} \sum_{k=1}^m T_k \le T^* \implies T_i \le T^* + t_j \le T^* + T^* = 2T^*$$ Garantía: $T \le 2T^*$ (2-aproximación).
2. Mejora LPT (Longest Processing Time First)

Regla Voraz Mejorada: Ordenar las tareas en orden decreciente de duración ($t_1 \ge t_2 \ge \dots \ge t_n$) antes de aplicar la asignación voraz.

Demostración de la Cota 3/2 (1.5-Aproximación):
Si $n \le m$, cada tarea va a una máquina distinta (óptimo).
Si $n > m$, cuando se asigna la tarea $m+1$, alguna máquina ya tiene al menos 2 tareas. Como las tareas están ordenadas decrecientes, cada una de las primeras $m+1$ tareas dura al menos $t_{m+1}$. Por lo tanto: $$T^* \ge 2 t_{m+1} \implies t_{m+1} \le \frac{1}{2} T^*$$ La última tarea asignada a la máquina máxima cumple $t_j \le t_{m+1} \le \frac{1}{2} T^*$. Sumando a $T_i - t_j \le T^*$: $$T \le T^* + \frac{1}{2} T^* = \frac{3}{2} T^*$$

7. El Problema del Viajante de Comercio (TSP)

El TSP general no admite ningún algoritmo de aproximación con factor constante a menos que P = NP. Sin embargo, cuando las distancias cumplen la desigualdad triangular ($c(u, w) \le c(u, v) + c(v, w)$, conocido como TSP Métrico), podemos diseñar algoritmos con garantías asombrosas.

Algoritmos de Construcción vs Mejora
  • Construcción: Crean un tour desde cero a partir de los datos.
    • Vecino más cercano: $O(n^2)$, ~25% sobre cota Held-Karp.
    • Tramo más corto (Kruskal-like): $O(n^2 \log n)$, ~15-20% sobre Held-Karp.
    • Christofides: $O(n^3)$, garantía teórica $3/2$ ($1.5$), ~6.7% sobre Held-Karp en la práctica.
  • Mejora (Búsqueda Local): Parten de una solución factible e intentan mejorarla iterativamente.
    • $k$-intercambios (2-opt, 3-opt): Reemplazar $k$ aristas.
    • Lin-Kernighan, Búsqueda Tabú, Simulated Annealing.
    • Algoritmo de Arora: PTAS para TSP euclídeo garantizando $(1 + 1/c)$.
¿Por qué funciona 2-Opt en Grafos Euclídeos?

"Si un ciclo Hamiltoniano se cruza a sí mismo, puede ser fácilmente acortado: basta con eliminar las dos aristas que se cruzan y reconectar los caminos resultantes mediante aristas que no se corten. El ciclo final es estrictamente más corto."

Fundamentos Randomizados

8. Algoritmos Randomizados: El Azar como Herramienta

El azar no se introduce en computación solo para videojuegos o simulaciones. Se utiliza cuando si el algoritmo se comportase de forma puramente determinística, fallaría o sería infinitamente más lento (por ejemplo, ante entradas patológicas construidas por un atacante o adversario).

🎰 Algoritmos Monte Carlo
Nicholas Metropolis (1947)
  • Tiempo de ejecución: Determinado y acotado (orden polinomial estricto).
  • Exactitud de la respuesta: Puede ser incorrecta con cierta probabilidad acotada.
  • Estrategia de mitigación: Repitiendo el algoritmo $k$ veces independientes, la probabilidad de error decrece exponencialmente a $(p_{\text{error}})^k$.
  • Ejemplos del curso: Algoritmo de Contracción de Karger (Min-Cut), Test de Primalidad de Miller-Rabin.
🎲 Algoritmos Las Vegas
László Babai (1979)
  • Exactitud de la respuesta: La respuesta es siempre correcta (o informa explícitamente que no pudo encontrarla).
  • Tiempo de ejecución: El tiempo es una variable aleatoria, pero su esperanza matemática es polinomial $E[T] = O(n)$.
  • Estrategia de mitigación: Si no encuentra solución, se repite el ensayo.
  • Ejemplos del curso: QuickSort Randomizado, QuickSelect (Selección de Mediana), N-Reinas aleatorio.
📐 Recordatorio Fundamental: Linealidad de la Esperanza
$$E[X + Y] = E[X] + E[Y]$$

¡Válido siempre, sin importar si las variables aleatorias $X$ e $Y$ son dependientes o independientes! Esta propiedad es la piedra angular de casi todas las demostraciones del paradigma.

9. Resolución de Colisiones en Redes (Rotura de Simetría)

El Problema: Un servidor atiende a $n$ clientes idénticos en intervalos de tiempo $t$. Los clientes no se conocen ni pueden comunicarse entre sí. Si 2 o más clientes intentan transmitir al servidor en el mismo lapso $t$, se produce una colisión, todos fallan y nadie se comunica.

Solución por Azar: Como no hay jerarquía para decidir quién va primero, usamos el azar para romper la simetría. Cada cliente intenta transmitir con probabilidad $p \in (0, 1)$, y con probabilidad $1-p$ decide esperar.

🎯 Deducción del Valor Óptimo de \(p\)

La probabilidad de que un cliente específico logre transmitir con éxito (él transmite y los otros $n-1$ callan) es:

$$P(\text{éxito individual}) = p \cdot (1 - p)^{n-1}$$

Para maximizar el throughput total de la red o la probabilidad de éxito, derivamos respecto a $p$ e igualamos a 0:

$$\frac{d}{dp} \left[ p(1-p)^{n-1} \right] = (1-p)^{n-1} - p(n-1)(1-p)^{n-2} = 0 \implies \mathbf{p = \frac{1}{n}}$$

Con $p = 1/n$, para $n$ grande la probabilidad de éxito se estabiliza en $\frac{1}{n} \left(1 - \frac{1}{n}\right)^{n-1} \approx \frac{1}{e \cdot n}$.

10. Corte Mínimo Global: Algoritmo de Contracción de Karger (1993)

Definición: Dado un grafo no dirigido $G=(V, E)$, un corte $(A, B)$ es una partición de los nodos en dos conjuntos no vacíos. El tamaño del corte es la cantidad de aristas que conectan un nodo de $A$ con uno de $B$. Buscamos el corte de menor tamaño posible.

Enfoque previo con Redes de Flujo: Como el grafo es no dirigido, transformamos cada arista en dos dirigidas con capacidad 1, fijamos un nodo $s$ y corremos Ford-Fulkerson para todos los posibles sumideros $t \in V \setminus \{s\}$ ($|V|-1$ ejecuciones). Es polinomial pero costoso.

Mecánica del Algoritmo de Contracción de Karger
  1. Comenzar con el multigrafo $G=(V, E)$ (admite aristas paralelas).
  2. Elegir una arista $e=(u, v)$ uniformemente al azar.
  3. Contraer la arista $e$: Fusionar $u$ y $v$ en un supervértice $w$, eliminar los bucles propios $(w, w)$, pero conservar las aristas paralelas hacia otros nodos.
  4. Repetir hasta que queden exactamente dos supervértices.
  5. Las aristas que sobreviven entre ambos supervértices constituyen el corte.

Análisis de Probabilidad y Amplificación de Éxito
📐 ¿Por qué la probabilidad no es exponencialmente pequeña?

Si el corte mínimo tiene tamaño $k$, cada nodo tiene grado al menos $k \implies |E| \ge \frac{nk}{2}$. La probabilidad de NO arruinar el corte en el primer paso al elegir una arista al azar es:

$$P(\text{éxito en 1 corrida}) \ge \frac{1}{\binom{n}{2}} = \frac{2}{n(n-1)}$$

Si repetimos el algoritmo $\binom{n}{2} \ln n$ veces independientes y nos quedamos con el menor corte hallado:

$$P(\text{fracasar en todas las corridas}) \le \left( 1 - \frac{1}{\binom{n}{2}} \right)^{\binom{n}{2} \ln n} \le e^{-\ln n} = \mathbf{\frac{1}{n}}$$

¡La probabilidad de éxito sube al $1 - \frac{1}{n}$ (más del $99.9\%$ para $n$ grande) en tiempo $O(n^4 \log n)$! Karger-Stein (1996) mejora esto a $O(n^2 \log^3 n)$ usando Divide y Conquista.

11. MAX 3-SAT: El Poder del Método Probabilístico (Garantía 7/8)

El problema de decisión 3-SAT es NP-Completo. Su versión de optimización, MAX 3-SAT, busca encontrar una asignación de verdad que maximice la cantidad de cláusulas satisfechas (es NP-Hard). Cada cláusula está compuesta por 3 literales disyuntos ($C_i = l_1 \lor l_2 \lor l_3$).

El Algoritmo Más Simple del Mundo

Para cada variable booleana $x_j$, lanzamos una moneda equilibrada: asignamos True con probabilidad $1/2$ y False con probabilidad $1/2$, de manera independiente.

🎯 Deducción Matemática de la Garantía 7/8

Para que una cláusula $C_i$ de 3 literales quede insatisfecha, sus 3 literales deben evaluarse en False:

$$P(C_i = \text{False}) = \left(\frac{1}{2}\right)^3 = \frac{1}{8} \implies P(C_i = \text{Satisfecha}) = 1 - \frac{1}{8} = \mathbf{\frac{7}{8}}$$

Definamos $Z_i = 1$ si $C_i$ está satisfecha y $0$ si no. La cantidad total de cláusulas satisfechas es $Z = \sum_{i=1}^k Z_i$. Por Linealidad de la Esperanza:

$$E[Z] = \sum_{i=1}^k E[Z_i] = \sum_{i=1}^k \frac{7}{8} = \mathbf{\frac{7}{8} k}$$

Como el óptimo no puede superar $k$, el número esperado de cláusulas satisfechas se encuentra a al menos $\frac{7}{8}$ ($87.5\%$) del óptimo.

🎉 Dato Curioso Demostrado en Clase:
Si una fórmula de 3-SAT tiene 7 o menos cláusulas ($k \le 7$), ¡siempre es 100% satisfacible!
Demostración: Con $k \le 7$, $E[Z] = \frac{7}{8} k > k - 1$. Como la cantidad de cláusulas satisfechas debe ser un número entero, existe al menos una asignación que satisface $k$ cláusulas (todas).

12. Selección de la Mediana y QuickSelect Randomizado

Dado un conjunto desordenado $S$ de $n$ elementos, queremos hallar el $k$-ésimo menor (para $k=n/2$, la mediana). Ordenar primero y tomar la posición $k$ toma $O(n \log n)$. Podemos lograr $O(n)$ tiempo esperado mediante QuickSelect con pivote aleatorio.

El Concepto de Elemento Central

Decimos que un elemento es central si al menos el $25\%$ de los elementos de $S$ son menores que él y al menos el $25\%$ son mayores (la mitad central de los datos, entre el percentil 25% y 75%).

25% Extremo Inferior 50% Elementos Centrales (Ideales) 25% Extremo Superior
  • Si el pivote elegido es central, se descarta al menos el $25\%$ del conjunto restante. El subproblema se reduce a lo sumo a $\frac{3}{4} |S|$.
  • Como el $50\%$ de los elementos son centrales, la probabilidad de acertar a uno con selección uniforme es $p = 1/2$.
  • La cantidad esperada de intentos para dar con un elemento central es $\frac{1}{p} = 2$ iteraciones.
📐 Suma Geométrica de las Fases
$$E[\text{Pasos}] \le \sum_{j} 2 c n \left(\frac{3}{4}\right)^j = 2 c n \sum_{j=0}^{\infty} \left(\frac{3}{4}\right)^j = 2 c n \cdot \frac{1}{1 - 3/4} = 8 c n = \mathbf{O(n)}$$

Es un algoritmo de tipo Las Vegas: siempre devuelve el elemento exacto y tarda $O(n)$ en promedio.

Estructuras de Datos

13. Estructuras de Datos Randomizadas: Skip Lists & Treaps

Los árboles binarios balanceados tradicionales (AVL, Red-Black) requieren complejas rotaciones y factores de balanceo deterministas. Las estructuras randomizadas aprovechan un teorema fundamental: "La altura esperada de un árbol binario de búsqueda creado en orden de inserción aleatorio es $O(\log n)$."

🪜 Skip Lists (Listas por Saltos)

William Pugh (1990) — La alternativa elegante a los árboles balanceados.

Consiste en una jerarquía de listas enlazadas superpuestas. Todos los elementos están en la lista base (Capa 0). Al insertar un nodo, se lanza una moneda: con probabilidad $p$ (comúnmente $1/2$) sube a la Capa 1; si vuelve a salir cara, sube a la Capa 2, y así sucesivamente.

Ruta Exprés: La búsqueda comienza en la capa más alta. Si el siguiente nodo es menor que la clave buscada, avanza horizontalmente ("skip"); si es mayor, desciende de nivel.
  • Búsqueda, Inserción, Borrado: $O(\log n)$ promedio con alta probabilidad.
  • Cantidad esperada de listas: $\log_{1/p} n$.
  • Espacio: $O(n)$ promedio.
🌲 Treaps (Tree + Heap)

R. Seidel & C. Aragon (1989) — Tree + Heap unidos.

Cada nodo almacena dos valores: Clave (mantiene propiedad de BST: izquierda menor, derecha mayor) y Prioridad Aleatoria (generada uniformemente al azar, mantiene propiedad de Max-Heap: padre mayor que hijos).

Operaciones mediante Rotaciones:
• Inserción: Se inserta como BST por clave en una hoja. Luego se rota hacia arriba (Left/Right Rotate) hasta que su prioridad respete el Heap.
• Borrado: Se asigna prioridad $-\infty$ al nodo a borrar y se lo rota hacia abajo hasta convertirlo en hoja, donde se elimina trivialmente.
  • El orden aleatorio de las prioridades simula que los nodos se hubieran insertado en orden aleatorio.
  • Operaciones en $O(\log n)$ con altísima probabilidad.
🗺️ Esquema Oficial de Skip List: Niveles y Ruta Exprés

Búsqueda del elemento 59: salta en la capa superior y desciende solo cuando el valor siguiente lo supera:

Ruta de búsqueda para 59: De 14 (nivel 2) mira 72 (>59) $\to$ baja a nivel 1 $\to$ avanza a 34 $\to$ 42 $\to$ mira 72 (>59) $\to$ baja a nivel 0 $\to$ 50 $\to$ 59 (Encontrado) en solo 5 comparaciones vs 6 secuenciales.

La rotación a izquierda preserva el orden de claves ($70 < 80$, hijo izquierdo) y restaura la propiedad de Max-Heap porque la prioridad $12$ ahora es superior a $10$.

14. Conteo Probabilístico con Memoria Acotada (Ejemplo Hamlet)

El Desafío: Queremos estimar la cantidad de palabras diferentes que contiene una obra colosal (ej. Hamlet de Shakespeare), pero disponemos de una memoria extremadamente limitada que solo permite almacenar hasta $m = 100$ palabras a la vez.

Mecánica de Rondas y Monedas del Algoritmo Oficial
  1. Llenamos la memoria con las primeras $m = 100$ palabras distintas que encontremos.
  2. Al llegar a 100, lanzamos una moneda por cada palabra guardada: si sale cara la conservamos, si sale cruz la descartamos (se espera que queden $\approx 50$ palabras).
  3. Continuamos leyendo. Cada vez que aparece una palabra ya vista, se lanza una moneda para ver si se mantiene.
  4. Cada vez que la memoria vuelve a llenarse a $m=100$, aumentamos la ronda $K$ y ahora se exigen $K$ monedas consecutivas para conservar cada palabra.
  5. Al final de la ronda $K$, cada palabra distinta sobrevive con probabilidad exacta $(1/2)^K$.
🎯 Estimación Matemática y Resultados del Material
$$\text{Total Estimado de Palabras} = |S_{\text{final}}| \cdot 2^K$$

Resultado real sobre Hamlet: Tras 6 rondas ($K=6$), terminaron $61$ palabras en memoria.
Estimación: $61 \cdot 2^6 = 61 \cdot 64 = \mathbf{3904\text{ palabras}}$.
Hamlet tiene exactamente $3967$ palabras distintas. ¡Menos de un 2% de error usando una memoria diminuta! Con $m=1000$, el error desciende a menos del $0.01\%$.

Hashing Teórico

15. Hashing Universal: Neutralizando el Peor Caso

El Peligro del Hash Fijo: Si elegimos cualquier función de hashing fija $h: U \to \{0, 1, \dots, n-1\}$, para cualquier universo $|U| > n^2$ siempre existirá un conjunto de $n$ elementos que producen exactamente el mismo valor de hash. Un adversario podría enviar esos elementos y degradar las operaciones a $O(n)$ lineal.

Definición de Clase Universal (Carter & Wegman 1979)

Una familia de funciones de hash $\mathcal{H}$ es Universal si para cualquier par de elementos distintos $x \ne y \in U$, al elegir una función $h \in \mathcal{H}$ uniformemente al azar:

$$\Pr_{h \in \mathcal{H}}[h(x) = h(y)] \le \frac{1}{n}$$

La probabilidad de colisión entre dos elementos cualesquiera es tan baja como si los asignáramos al azar en la tabla.

Construcción Algebraica con Números Primos
  1. Elegir un número primo $p \ge n$.
  2. Representar cada elemento $x$ como un vector de $r$ componentes: $x = (x_1, x_2, \dots, x_r)$ con $0 \le x_i < p$.
  3. Elegir un vector aleatorio de coeficientes $a = (a_1, a_2, \dots, a_r)$ con $0 \le a_i < p$.
  4. Definir la función de hash: $$h_a(x) = \left( \sum_{i=1}^r a_i x_i \right) \bmod p$$
Demostración de Cátedra: Si $x \ne y$, difieren en al menos una coordenada $j$ ($x_j \ne y_j$). La colisión $h_a(x) = h_a(y)$ ocurre si: $$a_j(y_j - x_j) \equiv \sum_{i \ne j} a_i(x_i - y_i) \pmod p$$ Como $p$ es primo y $y_j - x_j \not\equiv 0$, existe un único valor inverso para $a_j$ que satisface la igualdad. Como $a_j$ se eligió al azar entre $p$ posibilidades, la probabilidad de colisión es exactamente $\frac{1}{p} \le \frac{1}{n}$.

16. Ejercicios Propuestos de Clase Resueltos Paso a Paso

📝 Ejercicio 1: 2-Partition Problem (Demostración de 2-Aproximación)

Enunciado oficial: Dado un conjunto $S$ de números positivos, encontrar una partición de $S$ en dos subconjuntos $P_1$ y $P_2$ tal que el máximo de las sumas sea el mínimo posible.
Algoritmo propuesto: Inicializar $P_1 = \emptyset$ y $P_2 = \emptyset$. Para cada elemento $s \in S$, agregarlo al conjunto que tenga menor suma hasta el momento. Demostrar que es una 2-aproximación.

Demostración Formal:
  1. Sea $W = \sum_{s \in S} s$. En cualquier partición, la suma total es $W$, por lo que el óptimo $OPT$ cumple: $$OPT \ge \frac{W}{2} = \frac{1}{2} \sum_{s \in S} s \quad (\text{Cota A})$$
  2. Además, el elemento más grande debe estar en alguna de las particiones, por lo que: $$OPT \ge \max_{s \in S} s \quad (\text{Cota B})$$
  3. Supongamos sin pérdida de generalidad que $P_1$ termina con la mayor suma $S(P_1) \ge S(P_2)$. Sea $s^*$ el último elemento agregado a $P_1$. En el momento en que se le asignó $s^*$, $P_1$ tenía menor o igual suma que $P_2$: $$S(P_1) - s^* \le S(P_2)$$
  4. Sumando $S(P_1) - s^*$ a ambos lados: $$2(S(P_1) - s^*) \le S(P_1) - s^* + S(P_2) \le W \implies S(P_1) - s^* \le \frac{W}{2} \le OPT$$
  5. Despejando y aplicando la Cota B ($s^* \le OPT$): $$S(P_1) \le \frac{W}{2} + s^* \le OPT + OPT = \mathbf{2 \cdot OPT}$$
  6. Conclusión: El algoritmo voraz es garantizadamente una 2-aproximación. $\blacksquare$
📝 Ejercicio 2: Problema de las N-Reinas vía Algoritmo "Las Vegas"

Enunciado oficial: Proponer un algoritmo randomizado de tipo Las Vegas para resolver el problema de las N-Reinas. Puede encontrar una solución o fallar. Si falla, se repite el ensayo desde cero. ¿Cuál es la cantidad esperada de veces que hay que repetir el ensayo?

Diseño del Algoritmo y Análisis:
  1. Procedimiento por Columnas: Para la columna $c = 1 \dots N$, identificamos las filas donde colocar una reina no cause ataques con las reinas ya ubicadas.
  2. Elección Aleatoria: Entre las casillas libres válidas de la columna $c$, elegimos una al azar con probabilidad uniforme.
  3. Condición de Fallo: Si en alguna columna $c$ no queda ninguna casilla libre disponible, el algoritmo falla y se detiene (no hace backtracking pesado).
  4. Éxito: Si llega a ubicar las $N$ reinas sin conflicto, devuelve la solución (que es $100\%$ válida, condición de Las Vegas).
  5. Cantidad Esperada de Repeticiones: Si cada ensayo independiente tiene probabilidad de éxito $p > 0$, la variable aleatoria $X$ (cantidad de ensayos hasta el primer éxito) sigue una distribución geométrica: $$E[X] = \frac{1}{p}$$ Para $N=8$, empíricamente $p \approx 0.1293$ (aproximadamente 1 de cada 7.7 intentos triunfa), requiriendo en promedio solo $\approx 7.7$ corridas ultrarrápidas, mucho más veloz que explorar todo el árbol exhaustivo.
